# Contributing

## Prerequisites

- [Exact](https://github.com/expo/exact) — checked out next to this repository (`../exact`); set `EXACT` to use another path. Run `bun scripts/exact.mjs setup` there once
- [mise](https://mise.jdx.dev/) — installs the Bun version pinned in `.mise.toml` (Exact's toolchain needs Bun 1.4.2 or later)
- [just](https://just.systems/) — task runner
- [pre-commit](https://pre-commit.com/) — hook runner
- [Xcode](https://developer.apple.com/xcode/) 27.1 or later — only for the macOS and iOS hosts

## Setup

```sh
git clone https://github.com/connect0459/rss-reader
cd rss-reader
just setup
```

`just setup` installs the pinned Bun (`mise install`), installs the pre-commit hooks (`pre-commit install`), and generates `app.contract.d.ts`, the types `app.ts` imports.

### pre-commit hooks

To run all hooks manually:

```sh
pre-commit run --all-files
```

## Project structure

- `app.contract` — the view and the declarations: `shape`, `state`, `resource`, `mutation`, `action`, and `routes`.
- `app.ts` — the data module that answers each declaration by name, and the `grants` that bound what it may fetch, read, and write.
- `app.test.contract` — the tests: scripted taps and input, with a virtual clock the driver owns.
- `app.json` — the manifest.
- `exact.mjs` — generated by `exact new`; do not edit.
- `docs/todo.md` — the log of what's been verified, what broke, and why. Read it before changing the contract or the data module's boundary.

## Development workflow

| Command | Purpose |
| :--- | :--- |
| `just test` | Run `app.test.contract` on the web host |
| `just check` | Compile `app.contract` and print machine-readable diagnostics |
| `just verify` | Build, run the tests, and check the screens reached in light/dark, two widths, and the largest text size |
| `./exact.mjs web` | Serve the app on the web dev loop, reloading on every save |
| `./exact.mjs mac --run` | Build and launch on this Mac |
| `./exact.mjs ios --run` | Build and launch on an iOS Simulator |
| `./exact.mjs agent web tree` | Inspect or drive the running app |

Before opening a pull request, run:

```sh
just test && just verify
```

## Testing guidelines

This project follows **Red → Green → Refactor** (Detroit-school TDD):

- Write a failing test in `app.test.contract` first, then implement.
- Use real objects; mocks are only permitted at external boundaries. The data module's fixture feed stands in for the network, which is the external boundary.
- Test names describe **what behavior** is verified, not how.
- Coverage targets are agreed with the maintainer before implementation and recorded in `docs/todo.md`.
- Exception: exploratory spikes may skip test-first with explicit agreement — discard or rewrite as a proper implementation afterward.

## Commit format

```text
<type>(<scope>): <subject>
```

**Types**: `feat`, `fix`, `docs`, `style`, `refactor`, `tidy`, `test`, `chore`, `ci`, `perf`

**Scope**: area name when the change targets one specific part of the tree (`contract`, `data`, `tests`); omit for project-wide changes.

**Subject**: imperative mood, 72 characters max, no trailing period.

Examples:

```text
feat(contract): add a starred tab beside the reader tab
fix(data): keep the read state when a feed is refreshed
docs: record the Xcode 27.2 setup finding
```

## Pull request process

1. Fork the repository and create a branch: `feat/xxx`, `fix/xxx`, `docs/xxx`.
2. Follow the Red → Green → Refactor cycle for contract and data-module changes.
3. Run `just test` and `just verify`, and commit any resulting diffs.
4. If the change touches `grants`, confirm the list still names only what the app reads, writes, or fetches.
5. If the change affects the native hosts, confirm the relevant host still builds and runs (`./exact.mjs mac --run` or `./exact.mjs ios --run`).
6. Update `docs/todo.md` if the change resolves an open question or surfaces a new one — this file is the project's primary record, more so than commit messages alone.
7. Open a pull request.

## Code style

- No code comments unless the **why** is genuinely non-obvious.
- Prefer immutability; avoid mutable state unless necessary.
- Keep `grants` as narrow as the app's actual needs.
- All user-facing strings (test names, error messages, documentation) must be in **English**.
